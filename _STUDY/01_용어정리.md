## 🧱 A. 웹페이지를 이루는 3가지 (가장 중요)

홈페이지 하나는 **세 가지 재료**로 만들어집니다. 집 짓기에 비유하면:

| 용어 | 역할 | 비유 | 파일 확장자 |
|---|---|---|---|
| **HTML** | 구조·뼈대 (제목, 문단, 이미지, 버튼이 "무엇"인지) | 집의 **골조와 벽** | `.html` |
| **CSS** | 디자인 (색, 글꼴, 간격, 배치) | **벽지·페인트·가구 배치** | `.css` |
| **JavaScript (JS)** | 동작·기능 (클릭하면 열림, 챗봇 등) | **전기·수도 같은 작동 설비** | `.js` |

> [!important] 핵심
> - **HTML만 있어도 페이지는 뜬다** (밋밋하지만 내용은 다 보임).
> - CSS가 없으면 못생겼을 뿐이고, JS가 없으면 안 움직일 뿐입니다.
> - 그래서 우리는 **HTML(뼈대)부터** 배웁니다. → [[03_전체구조와_로드맵]] Phase 0

## 🌐 B. 사이트가 사람들에게 보이기까지

| 용어 | 뜻 | 비유 |
|---|---|---|
| **도메인 (Domain)** | 사이트 주소. 예: `cscam.co.kr` | 건물의 **주소** |
| **서브도메인 (Subdomain)** | 도메인 앞에 붙는 갈래. 예: `3dprinter.cscam.co.kr` | 같은 건물의 **호수(3층 301호)** |
| **DNS** | 도메인 ↔ 실제 서버를 연결해주는 전화번호부 | 주소 → 실제 위치를 찾아주는 **내비게이션** |
| **서버 (Server)** | 사이트 파일을 24시간 보관·전달하는 컴퓨터 | 24시간 문 연 **창고 겸 매장** |
| **호스팅 (Hosting)** | 서버에 내 사이트를 올려두는 서비스 | 창고 **임대** |
| **배포 (Deploy)** | 만든 사이트를 실제로 인터넷에 올리는 행위 | 완성된 상품을 **매장에 진열** |

> [!note] 우리 경우
> **서버를 직접 운영하지 않습니다.** GitHub Pages 같은 무료 서비스가 서버 역할을 대신 해줍니다.
> 이유는 → [[02_우리의_결정사항]]의 "서버는 필요 없다" 항목.

## 🗂️ C. 정적 vs 동적 (우리에게 중요)

| 용어 | 뜻 | 비유 |
|---|---|---|
| **정적 사이트 (Static)** | 미리 만들어둔 페이지를 그대로 보여줌. 방문자마다 내용이 같음 | 인쇄된 **카탈로그** |
| **동적 사이트 (Dynamic)** | 방문자·상황에 따라 내용이 바뀜 (로그인, 검색, 장바구니) | 매번 다르게 응대하는 **직원** |

> [!important] 우리는 **정적 사이트**입니다.
> 회사·제품 소개는 방문자마다 같으면 되니까요. 정적이라 **서버가 필요 없고, 빠르고, 안전하고, 공짜**입니다.
> 나중에 챗봇·회원가입 같은 "동적 기능"이 진짜 필요해지면 그때만 서버(서버리스)를 붙입니다.

## 📱 D. 반응형 / 모바일 (지금 겪는 문제!)

| 용어 | 뜻 | 비유 |
|---|---|---|
| **반응형 (Responsive)** | 화면 크기(PC·태블릿·폰)에 맞춰 배치가 자동으로 바뀌는 것 | 몸에 맞게 늘어나는 **스판 옷** |
| **뷰포트 (Viewport)** | 브라우저가 페이지를 보여주는 화면 영역. 폰이면 폰 화면 | 사진의 **액자 크기** |
| **미디어 쿼리 (`@media`)** | "화면이 768px보다 좁으면 이렇게 바꿔라"라고 CSS에 적는 규칙 | 상황별 **드레스코드 지침** |
| **모바일 퍼스트** | 처음부터 폰 화면 기준으로 설계하고, 큰 화면으로 넓혀가는 방식 | **작은 옷부터** 만들고 늘리기 |

> [!warning] 지금 우리 페이지의 문제 (2026-07-31 발견)
> - `viewport` 태그는 있음 ✅
> - 하지만 **미디어 쿼리(`@media`)가 0개** ❌ → 화면이 좁아져도 배치가 안 바뀜.
> - 표·카드가 PC 기준(4칸·7칸)으로 고정돼서, 폰에서 **찌그러져 깨짐**.
> - 자세한 진단·해결은 → [[04_작업일지]] 2026-07-31 항목.

## 🔧 E. 코드를 관리하는 도구 (Git / GitHub)

| 용어 | 뜻 | 비유 |
|---|---|---|
| **Git** | 파일 변경 이력을 저장·되돌리는 도구 | 무한 **되돌리기(Ctrl+Z) + 세이브 파일** |
| **저장소 (Repository / Repo)** | 한 프로젝트의 모든 파일 + 이력이 담긴 폴더 | 프로젝트 **전용 캐비닛** |
| **커밋 (Commit)** | "여기까지 저장!" 하고 한 시점을 도장 찍는 것 | 게임의 **세이브 지점** |
| **GitHub** | 저장소를 인터넷에 올려 백업·공유하는 서비스 | 코드용 **클라우드 드라이브** |
| **클론 (Clone)** | 원격 저장소를 내 컴퓨터로 복제해오는 것 | 캐비닛 **통째로 복사** |
| **GitHub Pages** | GitHub가 무료로 사이트를 배포해주는 기능 | 캐비닛 내용을 **바로 매장에 진열** |

## 🧩 F. 우리 구조에서 쓰는 용어 (조금 어려움 — 나중에 익숙해짐)

| 용어 | 뜻 | 비유 |
|---|---|---|
| **랜딩페이지 (Landing Page)** | 방문자가 처음 도착하는, 한 주제를 소개하는 페이지 | 매장 **쇼윈도** |
| **템플릿 (Template)** | 내용만 갈아끼우면 되는 페이지 틀 | **붕어빵 틀** |
| **컴포넌트 (Component)** | 재사용하는 부품 (헤더·푸터·버튼 등) | **레고 블록** |
| **디자인 토큰 (Design Token)** | 색·글꼴·간격 값을 한 곳에 모아둔 규칙 | 회사 **표준 색상·폰트 규정집** |
| **콘텐츠와 레이아웃 분리** | "내용(데이터)"과 "생김새(틀)"를 따로 관리 | **원고 ↔ 인쇄 서식** 분리 |
| **리팩토링 (Refactoring)** | 겉모습·기능은 그대로 두고 코드 속을 정리 | 겉은 그대로, **속 배선 정리** |
| **모노레포 (Monorepo)** | 여러 사이트를 저장소 하나에서 같이 관리 | 여러 매장을 **한 본사**에서 관리 |
| **정적 사이트 생성기** | HTML을 자동으로 만들어주는 도구 (예: Astro) | 붕어빵 **자동 기계** |

> [!note] 이 F 그룹은 [[03_전체구조와_로드맵]]에서 실제로 쓰면서 자연스럽게 익힙니다. 지금 다 이해 못 해도 정상입니다.

## 🤖 G. "에이전트와 함께 만든다"는 것

- **에이전트(Agent)** = 나(사령관)를 대신해 코드를 읽고·쓰고·검사하는 AI 작업자.
- 나는 **무엇을·왜** 만들지 결정하고, 에이전트는 **어떻게** 만들지 실행합니다.
- 그래서 사령관은 코딩 자체보다 **용어·개념·결정 판단력**을 갖추는 게 핵심입니다. → 그래서 이 교재가 있습니다.
